# Consensus and evidenceClaim evaluation uses `gl.vm.run_nondet_unsafe`. The leader independently fetches the repository, primary contribution and secondary evidence URLs and returns one bounded structured envelope. The validator independently repeats the fetch/classification boundary and rejects malformed results or disagreement on consequential fields. Expected model/source failures are represented only by bounded retryable error codes; the validator must reproduce the same failure class before it is accepted. Deterministic gates require confirmed attribution, pre-cutoff completion, scope match and no duplicate signal before a weight can be non-zero. Foundational impact requires two evidence paths.Accepted retryable errors become deterministic `INCONCLUSIVE` results with zero weight and a bounded retry budget. An unresolved `SUBMITTED` claim can be permissionlessly expired after the claims deadline so it cannot block epoch progress. Inconclusive or unavailable evidence has zero weight. The contract never converts model prose into a payout amount. The pool consumes only finalized integer weights.

## Validator disagreement handling

Consequential fields must be independently reproduced by the validator. Explanatory wording may differ, but malformed evidence, unsupported claims, or disagreement on the economic result must fail closed rather than allocate funds.
